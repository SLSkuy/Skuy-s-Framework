# 模拟核 Tick 出画面位姿

Respect: `CONTEXT.md`（画面节点、权威位姿、画面位姿、附身、本机 pawn、模拟核、对局）, `docs/adr/0004-match-state-starts-gameplay-local-pawn-after-level.md`（本机 pawn 晚于关卡、加入方本刀不 spawn、核不负责生成与附身）, `docs/adr/0005-match-state-orchestrates-no-game-manager.md`（对局态登记模拟核；不把呈现塞进流程核）.

## Problem Statement

对局里玩家 pawn 的移动和视角按模拟核配置的 Tick 直接写到角色 Transform 上。渲染帧比 Tick 密、或 Tick 被调低时，已附身角色在画面上跳变，没有两拍之间的画面位姿。相机跟的视角节点也只在 Tick 里转，一起一顿一顿的。玩家要的是权威仍按固定 Tick 算，眼睛看到的位移和朝向跟渲染帧走。

## Solution

模拟核继续用固定步长累加器推进权威位姿。每个本机 Tick 推进的实体带一个画面节点（包住现有 mesh）。每拍模拟前画面节点回到单位局部，让碰撞根和 mesh 朝向仍是权威。步进全部结束后，按时钟残差在上一拍与当前拍之间写出画面位姿：根位移写在画面节点上，身体与视角在 mesh / orientation 上插值旋转。生成、传送、回滚对齐时画面立刻跟上权威。加入方消费快照的延迟插值不在本刀。

## User Stories

1. As a 已附身的房主, I want 本机角色在渲染帧之间平滑移动, so that Tick 低于帧率时身体不跳格。
2. As a 已附身的房主, I want 视角和身体转向也按渲染帧平滑, so that 镜头和朝向不跟位移各顿各的。
3. As a 已附身的本机玩玩家, I want 同样的画面平滑, so that 本机玩和开多人不是两套手感。
4. As a 房主, I want 以后本机模拟出来的远端玩家也走同一套画面位姿, so that 同屏其他人不会只在 Tick 上跳。
5. As a 玩家, I want 权威移动仍按配置的 Tick 率步进, so that 手感和碰撞不跟显示器刷新绑死。
6. As a 玩家, I want 一帧里没有新 Tick 时画面仍继续插向下一拍, so that 高帧率中间那些空帧不是冻住的。
7. As a 玩家, I want 一帧里追上多拍时只在最后两拍之间插, so that 追帧不会把整段路径抹成一次滑动。
8. As a 玩家, I want 画面最多落后权威一拍, so that 去跳变的代价是可预期的短延迟，而不是再加网络缓冲。
9. As a 玩家, I want 碰撞和移动仍读权威位姿, so that 平滑画面不会让我钻墙或踩空。
10. As a 玩家, I want CharacterController 仍在实体根上, so that 画面节点动的时候碰撞胶囊不跟着漂。
11. As a 玩家, I want 模拟开始前画面节点是单位局部, so that 这一拍的前进方向仍来自权威 mesh，而不是上一帧的画面旋转。
12. As a 玩家, I want 出生时画面立刻等于权威, so that 第一帧不会从原点滑过来。
13. As a 玩家, I want 被传送时画面立刻跟上, so that 传送不会被插成滑行。
14. As a 玩家, I want 回滚写回权威后画面立刻对齐, so that 纠正不是慢慢漂过去。
15. As a 玩家, I want 冲刺仍走两拍插值, so that 冲刺看起来是快移而不是瞬切。
16. As a 玩家, I want 落地和跳跃的竖直位移也走画面位姿, so that 只有水平在平滑、竖直仍跳。
17. As a 玩家, I want 停住之后画面能落到权威位置, so that 残差用完后不会停在错误的半格上。
18. As a 玩家, I want 相机仍跟视角节点, so that 呈现窗口里视角节点已经是画面朝向，不必另做相机目标。
19. As a 玩家, I want 根旋转继续保持单位, so that 身体偏航和镜头俯仰仍分在 mesh 与 orientation 上。
20. As a 加入方, I want 本刀不要改我这边的远端表现, so that 快照消费仍等复制那一刀，不会被残差插值冒充。
21. As a 加入方, I want 客户端核仍然可以不开钟, so that 本刀不把预测步进偷运进来。
22. As a 开发者, I want 时钟残差由模拟核在步进之后写成画面, so that 呈现时机像「所有 Tick 跑完再 Render」，而不是每个实体自己 LateUpdate。
23. As a 开发者, I want 所有本机 Tick 推进的实体共用这套呈现, so that 以后房主上的远端 pawn 不必再开一条平滑路径。
24. As a 开发者, I want Replica 仍然不 Collect、不 Step, so that 画面位姿不把复制实体当成权威来插。
25. As a 开发者, I want 未初始化的实体不呈现, so that 半截登记不会写出垃圾画面位姿。
26. As a 开发者, I want 画面节点包住现有 mesh, so that 不必拆空逻辑 mesh 和模型。
27. As a 开发者, I want 配置里的快照延迟拍数继续无人消费, so that 本刀不会把残差 alpha 和远端快照缓冲混成一个旋钮。
28. As a 开发者, I want 不把移动改到渲染帧, so that 固定步长累加器仍是唯一权威时钟。
29. As a 开发者, I want 不把呈现接到流程核, so that 菜单/对局门闩仍然不管位姿。
30. As a 开发者, I want 不把生成与附身搬回模拟核, so that ADR-0004 仍然成立。
31. As a 开发者, I want 词表用权威位姿、画面位姿、画面节点, so that 不再出现主控角色、视觉代理、插值对象。
32. As a 开发者, I want 模拟器能在 EditMode 用已知 Tick 率开钟, so that 测试不必先走流程核切关。
33. As a 开发者, I want 停钟之后不再改画面节点, so that 离开对局拆核时不会残留呈现。
34. As a 开发者, I want 注销实体后不再为它呈现, so that 回收的本机 pawn 不会被下一帧再插一次。
35. As a 开发者, I want 动画仍挂在实体根上, so that 画面节点只偏移呈现，不另做一套 Animator。
36. As a 观察画面的玩家, I want 低 Tick 高帧率时运动看起来连续, so that 不必靠把 Tick 拉满去遮问题。
37. As a 观察画面的玩家, I want Tick 碰巧等于帧率时也不抖出额外误差, so that 残差接近 0 或 1 时画面就是当前或上一拍权威，而不是乱漂。

## Implementation Decisions

- 遵守 ADR-0004 / 0005：模拟核仍只持时钟与实体会话；本机 pawn 仍由对局态在关卡完成后生成并附身。本刀只补权威步进之后的画面位姿。
- 权威时钟保持固定步长累加器加追帧上限。不改成 Unity 物理固定更新，也不改成本机跟渲染帧移动。
- 模拟器每帧：先按累加器消耗整数拍（每拍呈现前把画面节点归单位局部，并把 mesh / orientation 掰回权威旋转，再拷上一拍权威、再步进）；全部拍结束后，不论本帧是否步进过，都用残差 alpha 写画面位姿。alpha 为累加器相对一拍时长的比例，范围约 `[0,1)`。
- 画面位姿 = lerp/slerp(上一拍权威, 当前权威, alpha)。根位移写到画面节点的世界位置（相对碰撞根的局部偏移）；mesh 与 orientation 在呈现时写成插值旋转。接受最多一拍画面落后。
- 画面节点是实体上的子节点，包住现有 mesh。碰撞根、CharacterController、Animator 仍在实体根。orientation 仍是根下视角节点；相机继续跟它，因为它在呈现窗口里已是画面朝向。
- 凡本机 Tick 推进的实体都走这套（房主上的本机 pawn 与以后的远端权威实体）。`IsReplica` 的实体仍跳过 Collect/Step，本刀也不为它们写残差画面位姿。
- 生成、Teleport、回滚写回：权威写完后画面位姿立即等于权威（上一拍与当前拍都对齐到新权威，避免插过去）。冲刺仍走普通两拍插值。
- 开钟前、停钟后、未登记或未初始化：不写画面位姿。
- 不读取、不接线快照延迟拍数、预测历史、世界快照消费。客户端模拟核本刀仍可不开钟。
- 语言：权威位姿、画面位姿、画面节点、模拟核、Tick、附身、玩家 pawn。避免主控角色、视觉代理、插值对象、把残差插值叫成快照插值。
- EditMode：模拟器必须能以已知 Tick 率开钟并 `Update`。若现有初始化绑资源门面，允许在同一条接缝下注入时钟参数，不得再增加第二条驱动（例如再测主机核或流程核）。

## Testing Decisions

- 只测对外行为：给定 dt 序列之后，碰撞根上的权威位置/朝向仍按固定 Tick 跳变；画面节点世界位置和 mesh / orientation 的画面朝向落在上一拍与当前拍之间；残差为 0 时画面等于上一拍权威、接近一拍时等于当前权威；无新 Tick 的帧画面仍随 alpha 前进；多拍追帧后只由最后两拍决定画面；生成后、Teleport 后、回滚写回后画面与权威重合；呈现前模拟读到的 mesh 朝向是权威而不是上一帧画面旋转；Replica 不步进故权威与画面都不被本刀残差驱动。不测累加器私有字段、不测流程核、不测相机组件内部、不测预制体 YAML 结构以外「能否按约定找到画面节点/mesh/orientation」、不测快照协议。
- **接缝（仅此一条）：模拟器的公开 Update。** 开钟、登记已初始化实体、喂 dt、读该实体权威位姿与画面位姿。不把 Tick 时钟模块、主机模拟核、流程核意图、实体模块私有字段当第二套驱动。允许注入已知 Tick 率。
- 仓库里编排测试接缝是流程核意图，上一刀明确不测核内部步进；本刀改的是核上呈现，因此接缝落到模拟器 Update，不再升到流程核。
- 好测试的例子：Tick 率 10、连喂远小于一拍的 dt，权威不动而画面沿上一拍→当前拍推进；刚好喂满一拍后权威跳到新位置、画面从旧权威开始重新插；一帧喂入超过两拍时长后画面落在最后两拍之间；Teleport 后下一帧画面不经过旧点；呈现后不归位就步进会失败——因此下一拍开始前 mesh 前进方向应与权威一致。

## Out of Scope

加入方快照延迟插值、世界快照收发、客户端预测与和解、输入缓冲排队再跑模拟、把 Tick 改到 Unity FixedUpdate、本机跟渲染帧移动、独立玩家控制器类型、相机另挂目标、拆空逻辑 mesh 与模型、提高或锁定 Tick 率来代替画面位姿、按名册全员 spawn、加入方本机 pawn、流程核/关卡控制改动、加载面板、动画参数平滑（配置里未接线的动画速度平滑也不在本刀）。

## Further Notes

三套常被混叫「插值」的东西里，本刀只做 Gaffer 残差画面位姿。FishNet 式图形子节点、Fusion 式「所有 Tick 之后再呈现」是时机与层级的对照，不是要引入那些库。配置里已有但未消费的快照延迟拍数留给复制刀。
