# 对局态自启动编排，关卡完成后附身本机 pawn

Respect: `CONTEXT.md`, `docs/adr/0001-host-starts-match-late-join.md`, `docs/adr/0002-match-owns-roster-procedure-only-gates.md`, `docs/adr/0003-resource-facade-vs-instance-facade.md`, `docs/adr/0004-match-state-starts-gameplay-local-pawn-after-level.md`.

## Problem Statement

对局已经能从菜单进去：名册、开听、切关卡、挂模拟核都通了，但关卡亮起来之后本机没有角色可操作。流程核现在会点名玩法粘合点去切关和启核，看起来像流程在管游戏内核。玩家要的是：本机玩或房主进关卡之后能附身自己的角色；加入方这一刀仍进空世界；流程只负责进出对局，不负责生成角色。

## Solution

菜单意图只建名册。进入对局流程态才登记玩法粘合点；粘合点自己向名册读会话角色，请求关卡控制加载关卡并启动模拟核。关卡加载完成之后，粘合点才让本机 pawn 模块生成本机那一枚角色并附身。加入方同样切关、挂客户端核，但不生成角色。切关或启核失败时粘合点发出编排失败，流程核作为门闩离开对局回到菜单。

## User Stories

1. As a 本机玩玩家, I want 点本机玩后立刻进入对局, so that 不必等角色出现才算开打。
2. As a 本机玩玩家, I want 关卡画面出来之后本机有一枚可操作角色, so that 我能在关卡里走动。
3. As a 本机玩玩家, I want 那枚角色的实体身份等于我的玩家身份, so that 名册上的我和关卡里的我是同一个人。
4. As a 本机玩玩家, I want 本机输入驱动那枚角色, so that 附身就是「这台机器在开这名玩家」。
5. As a 本机玩玩家, I want 角色出生在世界原点, so that 本阶段不必先做出生点规则。
6. As a 本机玩玩家, I want 离开对局后角色消失并回到菜单, so that 不会把 pawn 带回菜单。
7. As a 房主, I want 点开多人后立刻入座、开听并进入对局, so that 加入方在切关途中仍按中途入座处理。
8. As a 房主, I want 不必等关卡加载或 spawn 完成才算对局开始, so that 切关窗口不是第二道门闩。
9. As a 房主, I want 关卡加载完成后再看到本机角色, so that 不会在加载面板清空实例门面时把刚生成的角色清掉。
10. As a 房主, I want 本机只出现我自己的一枚 pawn, so that 这一刀不按名册给别人做本地角色。
11. As a 房主, I want 本机输入只附身我自己的 pawn, so that 不会误开加入方的实体。
12. As a 房主, I want 中途有人入座时我的本机角色仍在, so that spawn 不是每次 Admit 重来一遍。
13. As a 加入方, I want 被接受后进入对局并由关卡控制加载关卡, so that 我和房主一样处在对局里。
14. As a 加入方, I want 关卡出来后本阶段没有本地角色, so that 空世界是刻意的，等复制另刀再互看。
15. As a 加入方, I want 不必等待房主 spawn 完成就能进关卡, so that 我不会卡在房主的附身流程上。
16. As a 加入方, I want 被接受前仍在菜单且没有玩法粘合点, so that 失败时不会留下半套玩法对象。
17. As a 已在对局中的玩家, I want 加载面板在切关期间盖住画面, so that 我看不到半加载的关卡。
18. As a 已在对局中的玩家, I want 关卡完成后才感觉「在关卡里」, so that 流程上的对局开始和关卡亮起是两件事。
19. As a 玩家, I want 菜单里的场景加载完成不要生出对局角色, so that 回菜单或进菜单不会误 spawn。
20. As a 玩家, I want 回菜单后重新看到菜单入口且没有玩家 pawn, so that 对局拆除是干净的。
21. As a 玩家, I want 对局调试 HUD 仍能看名册并离开, so that 附身之后我还能解散或退出。
22. As a 玩家, I want 切关或启核失败时回到菜单, so that 我不会停在没有关卡也没有角色的假对局。
23. As a 开发者, I want UI 仍然只对流程核发意图, so that 界面不直接抓粘合点或本机 pawn 模块。
24. As a 开发者, I want 流程核在菜单意图里只建名册、不登记粘合点, so that 还在菜单时没有玩法对象。
25. As a 开发者, I want 进入对局流程态才登记玩法粘合点, so that 登记本身就是「开始编排」。
26. As a 开发者, I want 流程核不调用粘合点的切关、启核、spawn 方法, so that 流程核不再点名游戏内核。
27. As a 开发者, I want 粘合点自己向名册读会话角色, so that 流程核不必把房主/加入方当参数塞进玩法。
28. As a 开发者, I want 粘合点请求关卡控制加载关卡并启动模拟核, so that 名册对象继续不碰场景和时钟。
29. As a 开发者, I want 模拟钟可以在关卡完成之前转动, so that 开钟不是第二道开战门闩。
30. As a 开发者, I want 玩法阶段在关卡 Completed 之后才表示「在关卡里」, so that 阶段跟画面，不跟开钟、不跟附身。
31. As a 开发者, I want 粘合点转发关卡 Completed 给本机 pawn 模块, so that 模块不认识场景加载器。
32. As a 开发者, I want 本机 pawn 模块只在房主与本机玩时用房主玩家身份生成并附身, so that 加入方路径是空操作。
33. As a 开发者, I want 生成走实例门面和已有角色预制体, so that 不在关卡场景里预放角色、不手写 Instantiate。
34. As a 开发者, I want 模拟核只负责时钟与实体会话, so that 核不再声称开战时生成并附身。
35. As a 开发者, I want 关卡控制仍然只加载/切换关卡, so that 它不提供出生点、不回调玩法、不生成 pawn。
36. As a 开发者, I want 名册对象仍然不加载关卡、不启核、不 spawn, so that 连接/名册与玩法分得开。
37. As a 开发者, I want 拆对局时注销粘合点并回收本机 pawn, so that 实例门面不会在菜单里留着对局角色。
38. As a 开发者, I want 启核失败或关卡 Failed 时粘合点发出编排失败, so that 流程核只作为门闩离开对局。
39. As a 开发者, I want 粘合点不调用流程核的离开接口, so that 依赖方向仍是流程 → 编排失败通知 → 门闩。
40. As a 开发者, I want 不引入独立的玩家控制器类型, so that 附身就是本机输入源接到 pawn。
41. As a 开发者, I want 词表继续把这件事叫做附身而不是绑定控制器, so that 以后不会长出第二套控制器抽象。
42. As a 开发者, I want 本机 pawn 模块不进领域词表, so that 它只是粘合点子件，不是新的流程态。

## Implementation Decisions

- 遵守 ADR-0004：对局态登记粘合点即自启动编排；本机 pawn 在关卡 Completed 之后由本机 pawn 模块附身；加入方本刀不 spawn。
- 流程核仍是 UI 唯一意图入口（本机玩、开多人、加入、离开）。菜单意图只创建并打开名册对象（本机入座、按需开听）。进入对局流程态时才登记玩法粘合点。拆除对局时流程核仍注销粘合点与名册对象，并加载菜单入口场景。
- 删除流程核对粘合点的「初始化对局 / 进入对局并切关启核」调用。对局调试 HUD 仍由流程核在对局态显示；HUD 继续只通过流程核读名册，不抓粘合点。
- 粘合点在登记后的初始化里向名册对象读取会话角色。房主与本机玩走权威模拟核；加入方走客户端模拟核。粘合点不持有名册、不 Admit、不开听。
- 粘合点登记关卡控制并请求加载对局关卡，同时启动模拟核。开钟成功可以早于关卡完成。玩法阶段在请求切关后为「正在换关卡」，关卡 Completed 且场景名是对局关卡之后才为「在关卡里」。菜单场景的 Completed 不得把阶段打成「在关卡里」，也不得 spawn。
- 本机 pawn 模块是粘合点登记的对局期子模块，随粘合点拆除。粘合点订阅关卡加载完成/失败事件并转发给模块或自己处理失败；模块不订阅场景加载器。
- 仅当会话角色为房主（含本机玩）时，模块用名册上的房主玩家身份作为实体身份：经实例门面按资源位置生成已有网络角色预制体，登记到模拟核，把进程级本机输入源接到该实体（附身），变换放在世界原点。不在关卡场景预放角色，不经关卡控制取出生位。
- 加入方：模块空操作。不生成本机 pawn，不附身，不按名册给其他人做本地实体。
- 切关激活后的实例门面清空发生在 Completed 之前；spawn 必须在 Completed 之后。同一对局里重复 Completed 不得再生成第二枚本机 pawn。
- 启核失败或对局关卡 Failed：粘合点发出编排失败。流程核监听该通知并离开对局（回菜单、拆名册与粘合点）。粘合点不得反向调用流程核离开方法。
- 离开或解散：粘合点退出编排时停止模拟核、回收本机 pawn（取消附身并经实例门面回收）、注销关卡控制与本机 pawn 模块。随后流程核加载菜单。
- 模拟核接口与实现不再承担「开战生成并附身」。主机核只持有模拟器与时钟。
- 语言：玩家、玩家 pawn、附身、关卡、关卡控制、玩法粘合点、名册、流程。避免玩家控制器类型名、关卡开始初始化、游戏内核（口语里的流程侵入）把进程核和模拟核混为一谈。

## Testing Decisions

- 只测对外行为：流程态、是否已有粘合点、玩法阶段、关卡控制是否被要求加载、模拟核是否在跑、关卡完成后房主/本机玩是否恰好一枚 entityId 等于房主玩家身份的 pawn 且已附身、加入方完成后是否仍无 pawn、失败是否回菜单且无粘合点。不测模块私有状态、不测场景 YAML、不测核内部步进、不测 CharacterController 细节、不测资源句柄。
- **接缝（仅此一条）：玩法粘合点的对局编排表面。** 前置是名册对象已经按现有对局连接/名册 API 打开。测试登记粘合点（或通过流程核进入对局态让它被登记），断言它要求关卡控制加载并启动模拟核；再向现有关卡加载完成/失败事件注入「对局关卡完成 / 失败 / 菜单场景完成」，读取玩法阶段、模拟核上是否存在本机 pawn、流程是否回菜单。流程核只作为「何时登记 / 收到编排失败是否离开」的驱动，不把流程核内部状态机当接缝。本机 pawn 模块、场景加载器、实例门面内部池不是接缝。若 EditMode 无法走真实预制体 IO，允许在同一条接缝下替换实例门面与关卡 IO，不得替换粘合点本身。
- 仓库里几乎没有对等的 EditMode 玩法测试；上一刀接缝是名册对象。本刀把高度升到粘合点编排表面，因为要测的是切关完成之后的 pawn 与阶段，而不是 Admit。
- 好测试的例子：本机玩进入对局态后才有粘合点，菜单意图之后、换态之前没有粘合点；注入对局关卡 Completed 后阶段为在关卡里且模拟核上恰有一枚房主身份 pawn 并已附身；再注入一次 Completed 仍是一枚；加入方进入对局并 Completed 后无 pawn、阶段仍为在关卡里；注入菜单 Completed 不 spawn、阶段不变成在关卡里；注入对局关卡 Failed 后流程为菜单且无粘合点；离开后模拟核上无该 pawn。

## Out of Scope

加入方本机或远端 pawn、中途加入后的角色互看、按名册全员 spawn、出生点/关卡规则、玩家输入与世界快照、预测/插值、独立玩家控制器类型、本机玩家身份 API（加入方以后再暴露）、等关卡就绪再开钟、流程核点名切关/启核、把 spawn 放进模拟核或关卡控制、资源下载进度、再来一局、房主迁移、dedicated。

## Further Notes

上一刀把 pawn spawn 列为名册合并的 Out of Scope；本刀把它接回玩法粘合点，并且明确晚于关卡完成、早于复制同步。主机模拟核注释里「开战生成并附身」是过时职责，本刀删掉。实例门面仍是进程级生成入口，不要把它理解成玩家生成系统。
