# 对局态直接编排玩法，删除粘合类型

Respect: `CONTEXT.md`, `docs/adr/0001-host-starts-match-late-join.md`, `docs/adr/0002-match-owns-roster-procedure-only-gates.md`, `docs/adr/0003-resource-facade-vs-instance-facade.md`, `docs/adr/0004-match-state-starts-gameplay-local-pawn-after-level.md`（本机 pawn 晚于关卡完成仍有效；登记粘合点部分由 0005 取代）, `docs/adr/0005-match-state-orchestrates-no-game-manager.md`.

## Problem Statement

流程核和玩法粘合点抢同一段对局寿命：一个是进程级菜单/对局门闩，一个是对局级子系统，菜单里必须有前者、对局里才允许后者。类型名还都像在管「整场游戏」，开发时职责看起来重叠、离开路径绕事件回调。玩家要的行为不变：菜单进对局、对局里切关和开钟、房主/本机玩在关卡亮起后能附身，失败回菜单。开发者要的是只留一个流程核状态机开合对局，对局态自己接线，不要第三种对局对象。

## Solution

删除玩法粘合类型和关卡相位枚举。界面仍然只对流程核发意图。菜单意图只建名册；进入对局流程态时直接登记关卡控制、模拟核、本机 pawn；离开该态时拆除这些玩法对象。流程核拆除名册、取消未完成的加入、显示调试 HUD、加载菜单入口场景。切关或启核失败由对局态直接回到菜单，不再经编排失败事件。名册对象仍独立。玩家可观察的流程态仍只有菜单与对局。

## User Stories

1. As a 本机玩玩家, I want 点本机玩后立刻进入对局, so that 不必等关卡或角色出现才算开打。
2. As a 本机玩玩家, I want 进入对局后关卡开始加载, so that 我能进到对局发生的场景。
3. As a 本机玩玩家, I want 关卡画面出来之后本机有一枚可操作角色, so that 我能在关卡里走动。
4. As a 本机玩玩家, I want 那枚角色的实体身份等于我的玩家身份, so that 名册上的我和关卡里的我是同一个人。
5. As a 本机玩玩家, I want 本机输入驱动那枚角色, so that 附身就是这台机器在开这名玩家。
6. As a 本机玩玩家, I want 离开对局后回到菜单且角色消失, so that pawn 不会带回菜单。
7. As a 房主, I want 点开多人后立刻入座、开听并进入对局, so that 加入方在切关途中仍按中途入座处理。
8. As a 房主, I want 不必等关卡加载或 spawn 完成才算对局开始, so that 切关窗口不是第二道门闩。
9. As a 房主, I want 关卡加载完成后再看到本机角色, so that 不会在切关清空实例门面时把刚生成的角色清掉。
10. As a 房主, I want 中途有人入座时我的本机角色仍在, so that spawn 不是每次 Admit 重来一遍。
11. As a 加入方, I want 点加入后在被接受前仍停在菜单, so that 失败时我还在入口而不是假对局。
12. As a 加入方, I want 被接受前没有名册对象、无关卡、无模拟核、无本机 pawn, so that 取消或拒绝后菜单干净。
13. As a 加入方, I want 被接受后进入对局并由关卡控制加载关卡, so that 我和房主一样处在对局里。
14. As a 加入方, I want 关卡出来后本阶段没有本地角色, so that 空世界是刻意的，等复制另刀再互看。
15. As a 加入方, I want 被拒绝或连接失败后仍在菜单, so that 不会留下半套对局对象。
16. As a 已在对局中的玩家, I want 加载面板在切关期间盖住画面, so that 我看不到半加载的关卡。
17. As a 已在对局中的玩家, I want 对局调试 HUD 仍能看名册并离开, so that 我还能解散或退出。
18. As a 玩家, I want 切关失败时回到菜单, so that 我不会停在没有关卡的假对局。
19. As a 玩家, I want 模拟核启动失败时回到菜单, so that 我不会停在没有时钟的假对局。
20. As a 玩家, I want 回菜单后重新看到菜单入口, so that 对局拆除是干净的。
21. As a 玩家, I want 菜单场景加载完成不要生出对局角色, so that 回菜单不会误 spawn。
22. As a 开发者, I want UI 仍然只对流程核发意图, so that 界面不抓名册对象、不抓关卡控制、不抓模拟核。
23. As a 开发者, I want 菜单意图只建名册、不登记玩法对象, so that 还在菜单时没有关卡控制和模拟核。
24. As a 开发者, I want 进入对局流程态才登记关卡控制、模拟核和本机 pawn, so that 登记跟着对局态走，而不是另有粘合类型。
25. As a 开发者, I want 对局态向名册读会话角色再选择权威核或客户端核, so that 流程核不必把房主/加入方当参数塞进玩法。
26. As a 开发者, I want 对局态请求关卡控制加载对局关卡并启动模拟核, so that 名册对象继续不碰场景和时钟。
27. As a 开发者, I want 模拟钟可以在关卡完成之前转动, so that 开钟不是第二道开战门闩。
28. As a 开发者, I want 关卡完成后对局态才通知本机 pawn 模块, so that spawn 仍晚于切关清空实例门面。
29. As a 开发者, I want 不再存在玩法粘合类型, so that 流程核和对局对象不会再抢「整场游戏」这个名字。
30. As a 开发者, I want 不再存在关卡相位枚举, so that 玩家可观察的流程不会看起来像有第二套状态机。
31. As a 开发者, I want 有没有关卡只问关卡控制或当前场景, so that 切关不是菜单那样的流程态。
32. As a 开发者, I want 对局态离开时拆除关卡控制、模拟核和本机 pawn, so that 玩法对象的寿命等于对局流程态。
33. As a 开发者, I want 流程核在拆除时只取消加入、拆名册并加载菜单入口场景, so that 回菜单的门闩仍在流程核。
34. As a 开发者, I want 切关或启核失败由对局态直接切回菜单, so that 不再需要编排失败事件绕一圈。
35. As a 开发者, I want 对局态不反向调用流程核的离开接口, so that 失败就是状态机换态，拆玩法发生在离开对局态时。
36. As a 开发者, I want 调试 HUD 和光标仍由流程核在对局期间处理, so that 对局态只接线玩法对象。
37. As a 开发者, I want HUD 仍只通过流程核读名册, so that 界面不抓名册对象。
38. As a 开发者, I want 名册对象仍然不加载关卡、不启核、不 spawn, so that 连接/名册与玩法分得开。
39. As a 开发者, I want 关卡控制仍然只加载/切换关卡, so that 它不启核、不 spawn、不管名册。
40. As a 开发者, I want 各子系统的帧循环仍由进程级系统管理负责, so that 流程核不是 Tick 调度器。
41. As a 开发者, I want 对局态内不再抽第二层总控类型, so that 不会把粘合点换个名字加回来。
42. As a 开发者, I want 词表使用流程核、对局、关卡控制、名册, so that 不再使用玩法粘合点。
43. As a 开发者, I want 本机 pawn 晚于关卡完成、加入方本刀不 spawn 的行为保持, so that 本刀只改接线主人，不改附身时机。
44. As a 开发者, I want 房主退出仍解散并对所有人回菜单, so that 名册侧的解散路径不变。
45. As a 开发者, I want 加入尚未完成时离开会取消加入, so that 菜单不会留下半条连接。

## Implementation Decisions

- 遵守 ADR-0005：删除玩法粘合类型与关卡相位枚举；退役「玩法粘合点」一词。对局流程态直接登记关卡控制、模拟核、本机 pawn。ADR-0004 中本机 pawn 晚于关卡完成、加入方本刀不 spawn、对局可早于 pawn 仍有效。ADR-0002 的名册独立、流程只进出对局仍有效。
- 流程核仍是 UI 唯一意图入口（本机玩、开多人、加入、离开）。它是进程寿命上的菜单/对局状态机，不是整段进程的框架壳，也不调度子系统 Tick。
- 菜单意图只创建并打开名册对象。进入对局流程态才登记玩法对象；尚未被接受的加入仍停在菜单，只有连接、没有名册、没有玩法对象。
- 对局态 Enter：向名册读会话角色；登记关卡控制并请求加载对局关卡；按角色启动权威或客户端模拟核；登记本机 pawn 模块；订阅关卡加载完成/失败。流程核在对局期间显示调试 HUD 并处理光标，不在此登记玩法对象。
- 关卡 Completed 且场景名是对局关卡：对局态通知本机 pawn 模块（房主/本机玩生成并附身，加入方空操作）。菜单场景 Completed 不得 spawn。同一对局里重复 Completed 不得再生成第二枚本机 pawn。
- 关卡 Failed（对局关卡）或启核失败：对局态把流程切到菜单。不引入编排失败事件，对局态也不调用流程核的离开方法；换态后由对局态 Leave 拆玩法。
- 对局态 Leave：停止并注销模拟核、回收本机 pawn、注销关卡控制与本机 pawn 模块、退订关卡加载事件。
- 流程核 TearDown：清加入进行中标志、隐藏 HUD、解绑加入 Handler；若仍在加入则停客户端连接；否则退订名册结束、注销名册对象、加载菜单入口场景。不在此处注销关卡控制/模拟核/本机 pawn（那是对局态离开的责任）。离开对局的玩家意图仍是切到菜单，从而先走对局态 Leave 再走菜单与 TearDown。
- 名册结束（房主解散等）仍把流程切到菜单，随后同一套 Leave + TearDown。
- 不把 `GameManager` 升成进程级单例；不对局态内再抽不登记到全局的第二层总控。关卡控制、系统管理、名册对象保持现有分工。
- 语言：流程核、菜单、对局、名册、关卡、关卡控制、附身、玩家 pawn。避免玩法粘合点、GameManager 作流程或粘合类型、游戏内核、会话壳、把切关当成第三种流程态。

## Testing Decisions

- 只测对外行为：流程态是菜单还是对局；名册对象是否存在；关卡控制是否被要求加载对局关卡；权威核或客户端核是否在跑；关卡完成后房主/本机玩是否恰好一枚与房主玩家身份相同的已附身 pawn；加入方完成后是否仍无 pawn；失败或离开后是否回到菜单且无名册、无关卡控制、无模拟核、无本机 pawn、无粘合类型。不测状态机私有字段、不测场景 YAML、不测核内部步进、不测加载面板内部、不测实例门面池。
- **接缝（仅此一条）：流程核的公开意图。** 测试通过本机玩、开多人、加入完成/失败、离开驱动流程；向现有关卡加载完成/失败事件注入「对局关卡完成 / 失败 / 菜单场景完成」。读取流程态与全局是否已登记名册、关卡控制、模拟核、本机 pawn，以及模拟核上是否存在本机 pawn。不把流程核内部状态机当接缝，不保留已删除粘合点的编排表面，不对局态 Enter/Leave 做第二套驱动。若 EditMode 无法走真实预制体或开听 IO，允许在同一条接缝下替换实例门面与关卡/网络 IO，不得为此恢复粘合类型。
- 仓库里上一刀的粘合点编排 EditMode 测试已不在；本刀把接缝升到流程核意图，因为接线主人改成了对局态，对外仍只应看见流程意图和登记结果。名册对象的连接/Admit 接缝不在本刀重开。
- 好测试的例子：本机玩之后、进入对局态之前没有关卡控制和模拟核；进入对局态后关卡控制被要求加载且权威核在跑；注入对局关卡 Completed 后恰有一枚房主身份 pawn 并已附身；再注入一次 Completed 仍是一枚；加入完成前流程为菜单且无玩法对象；加入完成后客户端核在跑、Completed 后无 pawn；注入对局关卡 Failed 或启核失败后流程为菜单且无残留；离开后菜单入口加载且玩法对象与名册都不在；进程中不存在粘合类型可被登记。

## Out of Scope

加入方本机或远端 pawn、中途加入后的角色互看、按名册全员 spawn、出生点/关卡规则、玩家输入与世界快照、预测/插值、独立玩家控制器类型、本机玩家身份 API、等关卡就绪再开钟、把 spawn 放进模拟核或关卡控制、把名册并进流程核、把 `GameManager` 升成进程级 FSM、资源下载进度、再来一局、房主迁移、dedicated、加载面板内部、子系统 Tick 调度器改设计。

## Further Notes

本刀是接线主人的搬迁，不是新玩法。上一刀「对局态登记粘合点」的测试口径作废。流程核管玩法流程（菜单/对局），不管进程级框架服务。对局态是玩法接线处，不是第二套流程状态机，也不是关卡控制本身。
