# 房主即开战与中途入座

Respect: `CONTEXT.md`, `docs/adr/0001-host-starts-match-late-join.md`.

## Problem Statement

学习用的多人流程没有把房间当成准入门槛：本机房会跳过聚会直接开战并生成角色；多人房主和加入方停在一个名不副实的大厅；Join 响应是空的；开战 spawn 不读名册；切关卡会和进程壳抢生命周期。上一轮局内同步因为缺少房间抽象，整条启动数据流别扭。现在需要先把「房主进关卡、别人中途入座」做成完整会话，再碰输入和快照同步。

## Solution

玩家只看见菜单和对局。房主（或本机房）从菜单一次完成建房、入座、开听（若接远端）并进入关卡；加入方在 Join 被接受后才拥有房间，并进入已经开始的对局。名册以房主分配的玩家身份为准，双方对齐。本阶段结束对局即解散房间并回菜单。关卡只承载几何；进程壳留在入口的根对象上。

## User Stories

1. As a 玩家, I want 从菜单选择本机玩、开多人、或加入, so that 我不必先理解大厅或房间码。
2. As a 玩家, I want 菜单在无房间时才出现那三个入口, so that 我不会在对局中误开第二套会话。
3. As a 本机房玩家, I want 点本机玩后进入关卡并开始对局, so that 单人路径和多人路径共用房间，而不是旁路。
4. As a 本机房玩家, I want 房间容量为 1 且不接受远端加入, so that 不会有人连进我的本机对局。
5. As a 房主, I want 点开多人后本机立刻入座并开始对局, so that 我不在一个等人大厅里空等。
6. As a 房主, I want 一点开多人，对局在协议上就已开始（不必等关卡加载或角色生成结束）, so that 加入方在切关途中也能按中途入座处理。
7. As a 房主, I want 进入关卡后再生成本机那一枚 pawn, so that 角色不会留在被卸掉的菜单场景里。
8. As a 房主, I want 本机 pawn 的实体身份等于我的玩家身份, so that 下一刀同步不必换主键。
9. As a 房主, I want 开听之后加入方可以连上来, so that 别人能进已经在打的房间。
10. As a 加入方, I want 点加入后先连接、在被接受之前没有房间对象, so that 失败时不会留下假会话。
11. As a 加入方, I want 用现有客户端配置的本机地址和端口加入, so that 本阶段能在本机两进程里验证，而不做房间码和发现。
12. As a 加入方, I want Join 响应告诉我是否被接受、我的玩家身份、房主身份、完整名册、以及对局已开始, so that 我能对齐房主的名册并进入对局。
13. As a 加入方, I want 被拒绝、连接失败、房间已满或房主已解散时回到菜单并拆掉客户端网络, so that 我不会停在空房间里。
14. As a 加入方, I want 接受后才创建本进程房间并写入名册（含我自己）, so that 名册不是空壳。
15. As a 加入方, I want 接受后进入关卡并挂上客户端模拟核, so that 我处在对局寿命里，而不是还停在菜单。
16. As a 加入方, I want 本阶段不生成任何 pawn, so that 房间门闩和局内同步可以分开验证。
17. As a 房主, I want 只生成本机那一枚 pawn，不为名册上的加入方生成角色, so that 下一刀同步不会先拆掉错误的 LocalPlay 群体。
18. As a 已在对局中的玩家, I want 看见当前名册（人数与玩家身份）, so that 我知道谁在这局里。
19. As a 已在对局中的加入方, I want 别人后来入座或离开时名册更新, so that 我看到的名单和房主一致。
20. As a 房主, I want 每次入座或离座后向在席加入方广播完整名册, so that 先到的人也能看见后到的人。
21. As a 后到的加入方, I want 进房时拿到当时完整名册, so that 我不缺已经在局里的人。
22. As a 加入方, I want 对局进行中仍能入座, so that 「主机先打、别人再进」成立。
23. As a 房主, I want 房间最多 4 名玩家, so that 满员时 Join 被拒绝。
24. As a 加入方, I want 离开对局后只从名册消失、对局对其他人继续, so that 我退出不会拆掉房主的局。
25. As a 房主, I want 离开或解散时所有加入方回到菜单, so that 没有无主房间。
26. As a 房主, I want 结束对局等于解散：卸关卡、拆房间和网络、回到菜单, so that 本阶段不必支持同一房间再开一局。
27. As a 加入方, I want 收到解散后回到菜单并拆掉客户端网络, so that 我不会对着已死的房主挂着。
28. As a 玩家, I want 关卡场景只是几何与对局视野, so that 切关不会再启动第二套进程壳。
29. As a 玩家, I want 菜单场景作为入口、进程壳在切关后仍在, so that 会话和流程不会跟菜单一起被卸掉。
30. As a 玩家, I want 回菜单时重新看到菜单入口且只有一份进程壳, so that 不会叠两个核心对象。
31. As a 玩家, I want 对局期间用常驻调试 HUD 看名册并离开, so that 菜单画布随入口场景卸掉之后我仍能操作会话。
32. As a 开发者, I want UI 只对流程核心发意图, so that 界面不直接抓战局管理器。
33. As a 开发者, I want 传输沙盒场景可以留下, so that 我仍能单独测 TCP/KCP，但它不得成为会话主人。
34. As a 开发者, I want 旧的本地同步测试场景不再当作可玩入口, so that 不会再走没房间的旁路。
35. As a 开发者, I want 流程对外不再把大厅当成玩家可停留的一站, so that Host/本机不会停在空大厅、加入方也不会在未入座时假装已入房。
36. As a 房主, I want 加入请求不把对方自报的传输客户端身份当成玩家身份, so that 名册键始终是我分配的玩家身份。
37. As a 加入方, I want 连接身份只用于传输, so that 掉线按连接找到玩家并从名册删除。
38. As a 本机房玩家, I want 结束或离开后回到菜单且房间消失, so that 本机路径和多人解散一致。
39. As a 房主, I want 在加入方 Join 尚未完成时仍视为对局已开始, so that 不会对同一加入方先说不在局里再说在局里。
40. As a 加入方, I want 不必等待房主 spawn 完成就能进关卡, so that 切关窗口不是第二道门闩。
41. As a 玩家, I want 对局中才允许 Tick 和模拟核, so that 菜单阶段不会跑战斗步进。
42. As a 开发者, I want 本阶段不接线玩家输入与世界快照消息, so that 房间完成定义不被同步工作吞掉。

## Implementation Decisions

- 流程核心仍是 UI 的唯一意图入口：本机玩、开多人、加入、离开/解散。玩家可观察的流程态只有菜单与对局；大厅不得再作为可停留状态。内部允许「已有房间、关卡尚未就绪」的短暂间隙，但不得对 UI 暴露为大厅。
- 会话主人仍是战局管理器：建本机房、建多人房（开听）、加入远端（先连接后入座）、入座、离座、解散、开战、结束对局。房间对象持有名册；模拟核与对局壳只在开战之后存在。
- 本机房：容量 1、不接远端、本机入座。开多人房：容量 4、接远端、本机入座并开听。加入方：可靠连接成功后发加入请求；被接受前不得 `new` 房间。
- 房主分配单调递增的玩家身份；本机连接用固定的本地连接键映射到该身份。加入请求可携带传输侧客户端身份，但不得用它当名册键。加入响应必须带回：是否接受、自己的玩家身份、房主玩家身份、完整名册、对局已开始（开听之后恒为真）。
- 入座或离座后，房主对仍在席的加入方广播完整名册（不做增量、不保留已离开者给 UI）。对局进行中允许入座；满员拒绝。
- 不用「开战」消息作为加入方进对局的信号。加入方仅在加入响应为接受时进入对局并切关卡。
- 切关顺序：先加载关卡场景，再开战（再 spawn）。加入方同样：接受 → 切关卡 → 挂客户端核，本阶段不 spawn。
- 关卡场景去掉残留的第二套游戏核心。入口根对象上的核心单例负责进程壳跨场景存活。回菜单时单加载入口场景；重复的根对象按现有单例去重拆掉；流程回到菜单。
- 本阶段结束对局与解散相同：停核、清名册、停网络、卸关卡、回菜单。房主离座或进程拆会话即解散；加入方离座只删名册并广播，不结束对局。
- 开战身体：本机房与房主按名册只生成本机一枚 pawn，实体身份等于玩家身份；多人房主该 pawn 为权威侧。加入方挂客户端核但不生成 pawn。不登记、不发送、不处理玩家输入与世界快照。
- 对局调试 HUD 挂在常驻 UI 层：显示名册；加入方离开；房主解散。
- 加入地址本阶段使用现有客户端网络配置（本机回环与配置端口）。连接失败走现有可靠连接失败路径，不另做房间超时状态机。
- 传输测试面板可保留，禁止登记战局管理器或充当会话主人。旧同步测试场景不作为可玩路径。
- 语言与边界以领域词表为准：房间、名册、对局、关卡、房主、加入方、玩家、连接。避免把大厅当房间，避免把连接当玩家。

## Testing Decisions

- 只测对外行为：流程意图之后，房间是否存在、名册是否对齐、流程态是否为菜单或对局、是否开听、是否已切关并开战、失败是否回到无房间菜单。不测私有字段、消息函数名或核内部步进。
- **接缝（仅此一条）：战局管理器对外的会话 API，以及它发出/收下的加入与名册消息。** 流程核心是该 API 的编排者（切关顺序、菜单/对局），不要为测试再引入第二套编排层。能在不连真实传输的情况下向战局管理器注入「某连接加入请求 / 加入响应 / 连接移除」，并读取活动房间名册、会话角色、对局是否已提交。需要场景的部分（先切关再开战、回菜单只留一份进程壳）用同一套意图入口做 PlayMode，仍断言战局管理器与当前流程态，而不是场景 YAML。
- 仓库里几乎没有对等的 EditMode 玩法测试；传输测试面板是手动沙盒，不是本特性的自动测试范本。新测试放在测试程序集，面向战局会话，不要去扩传输面板。
- 好测试的例子：本机玩之后容量 1 且名册仅本机、再 Admit 远端失败；开多人后加入响应含玩家身份与完整名册且对局已开始；第二个加入方入座后第一个加入方也能看到更新后的完整名册；满员拒绝且被拒方无房间；加入方离开名册减少但对局仍在；房主离开后双方无活动房间；被拒/失败后无房间且不在对局。

## Out of Scope

准备就绪、房间码、局域网发现、IP 输入 UI、重连、房主迁移、同一房间再开一局、中途加入后的角色互看、玩家输入与世界快照、预测/插值、非玩家实体身份、dedicated server、把传输测试改成会话主人。

## Further Notes

上一刀若把所有名册成员生成成本地角色，会在同步阶段再拆一次；本阶段刻意让加入方进「空对局」。关卡加载器有最短加载时间，加入方可能在房主 spawn 前入座，这是允许的。
