# 实例池按资源分组活着，纯对象池另算

场景里的实例只进实例池，按资源位置借还。没有场景外形的对象进纯对象池。两套池都要求对象能重置，但纯对象池不认识资源位置，也不参加换场景。

调用方给资源位置指定资源分组；不指定就是临时分组。该位置第一次进池时分组固定，之后不能改到另一组。加载失败且池里已没有这个位置时，可以重新选组。

分组决定两件事：换场景时清除还是留下，以及每个资源位置最多留下多少空闲实例。超出空闲上限的还池实例被销毁，不等待空闲超时。默认临时分组、特效和预制体随场景清除；界面和音频留下。资源在仍有借出、空闲或等待加载时不卸。

## 考虑过的做法

- 换场景时清空整个实例池。界面和音频会跟关卡实例一起消失。
- 只靠统一的空闲超时回收。一次峰值会把大量空闲实例留到超时，特效和临时物体尤其容易胀池。
- 把分组做成可序列化字典。运行时查找方便，检查器里难以逐项改策略，因此策略仍是按分组排列的列表，查找只在运行时建。

## 后果

- 不进池实例不占用空闲名额，也不挂在分组下；释放时销毁。
- 调试只在打开查看时清点现有借出、空闲和等待，不在借还路径上另记账。
