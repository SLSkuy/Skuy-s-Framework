# 业务只使用玩家号

连接、玩家、实体是三个身份。游戏业务只使用玩家号。connectionId 只表示远端客户端，并且只出现在对局的入座与离座边缘。entityId 留在生成与模拟中，不必等于玩家号。

## 考虑过的做法

- 把 connectionId 当成传输会话，或让对局绑定会话。会话会在重连时换绑，座位不能跟着换。
- 传输一连上就入座，或一断开就离座。入座是单独的一步。断线有宽限，宽限期内座位和玩家实体都还在。
- 让实体号等于玩家号。非玩家实体没有玩家，两个号不是一回事。
- 主动离开后立刻拆掉连接。主动离开只断开传输会话，连接仍走重连宽限。

## 后果

- 传输会话的连上与断开不到达业务。握手之后才有连接，入座之后才有玩家，生成层再用玩家号解析实体号。
- 宽限期内玩家与其玩家实体都留在场上。宽限结束、连接被移除时，若玩家仍在座，则玩家离座，其玩家实体消失。尚未入座的连接被移除时，没有玩家可离开。
- 玩家主动离开时只断开传输会话，并进入重连宽限。宽限内重连仍是原来的玩家号；宽限结束才离座。离座后的玩家号不能领回。
- connectionId 为 0 表示房主没有连接，不对应传输客户端，也不对其做移除。房主结束对局时，对局消失，所有在座玩家离座，远端连接一并移除。这不是某一条连接的回调。
