# 名册属于对局，菜单只进出对局

没有房间，也没有会话。名册、开听与入座属于对局里的连接/名册一侧，不塞进玩法粘合点。菜单流程只负责进入和离开对局，不加载关卡。玩法系统由独立的粘合点编排；关卡的加载与切换由关卡控制负责。

**Considered Options**: 保留「会话壳 + 房间名册」（与「开始即对局、只有一个聚会」重复）；把名册、连接和玩法一并塞进粘合点（无法区分玩家连接与游戏玩法）；让粘合点兼做关卡规则。

**Consequences**: `ADR-0001` 的房主即开战、加入即中途入座仍然有效；其中「房间仍是名册权威」不再成立——名册进对局的连接/名册对象（合并后的 `BattleManager`），`BattleRoom` 删除。`GameManager` 只做玩法胶水，不持有名册、不 Admit、不开听。关卡控制第一期就独立，只负责加载/切换关卡。加入尚未被接受时没有对局：Procedure 登记 `NetClient`，接受后 `BattleManager` 接管同一条连接；失败或取消则 Procedure 注销。本机玩与开多人直接创建 `BattleManager`，并另建 `GameManager` 做玩法编排。
