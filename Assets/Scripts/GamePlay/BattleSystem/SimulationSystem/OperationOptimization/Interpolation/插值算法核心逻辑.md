# 快照插值核心逻辑

客户端收到远端实体的权威快照后，先缓存，再按照独立推进的播放时间生成画面。播放时间稍微落后于已收到的最新快照，保留一段余量来吸收网络延迟和收包抖动。

理解算法只需要掌握：**比较收到的位置与播放位置，余量偏多就稍微加速，偏少就稍微减速；余量耗尽后暂停，重新积累到目标余量再继续。**

## 关键概念与变量

| 变量 | 含义 |
| --- | --- |
| `_currentPlaybackTick` | 当前画面播放到的快照 Tick，可以是小数 |
| `latestReceivedSnapshotTick` | 已收到的最新快照 Tick |
| `oldestBufferedSnapshotTick` | 缓存中仍然保留的最旧快照 Tick |
| `_targetBufferedTicks` | 希望保留的可播放余量，即配置的插值延迟 Tick 数 |
| `remainingSnapshotTicks` | 最新收到的 Tick 减去当前播放 Tick，表示剩余可播放的时间跨度 |
| `_smoothedRemainingSnapshotTicks` | 平滑后的余量，用于判断是否需要调速 |
| `playbackSpeedMultiplier` | 播放速度倍率，正常为 1，范围为 0.95～1.05 |
| `_hasStartedPlayback` | 是否已经建立初始播放位置 |
| `_isWaitingForSnapshots` | 是否因为余量耗尽而暂停，等待新快照积累 |

这里的 Tick 是快照时间单位，不是画面渲染帧，也不等于缓存里的快照条数。丢包时，相邻两个快照的 Tick 可以不连续。

快照序号的增长速度必须与 `_snapshotTickRate` 一致。例如快照频率为 30 Hz，3 Tick 的目标余量对应约 100 毫秒。

## 1. 收到快照：只缓存，不立即改变画面

`AddFrame()` 为每个实体维护独立的 `SnapshotBuffer`。缓存按 Tick 排序，同一 Tick 的快照被覆盖，超过容量后淘汰最旧快照；默认容量为 32 条。

所有远端实体共用一个播放头。`TryGetLatestTick()` 从各实体缓存中取最新 Tick 的最大值，以及最旧 Tick 的最小值，作为整体时间范围。具体实体仍使用自己的快照插值。

## 2. 首次播放：先建立缓冲窗口

任意一个实体缓存至少有两条快照，且最旧到最新的 Tick 跨度达到目标余量后，允许开始播放。

初始播放位置为：

```text
目标播放位置 = max(最旧缓存 Tick, 最新收到 Tick - 目标余量)
```

例如已经收到第 100～106 Tick，目标余量为 3 Tick，就从第 103 Tick 开始播放，保留后面的 3 Tick。

## 3. 正常播放：连续推进，温和调速

每个画面帧都根据经过的时间推进播放头：

```text
播放头前进量 = 本帧耗时 × 快照频率 × 播放速度倍率
```

例如画面为 60 FPS、快照频率为 30 Hz，正常速度下，每个画面帧前进约 0.5 Tick。因此即使本帧没有收到新包，也可以继续利用已有快照生成画面。

根据余量相对目标的偏差，调整播放速度：

| 平滑后的余量 | 策略 |
| --- | --- |
| 与目标相差不超过 0.5 Tick | 保持正常速度 |
| 比目标多出超过 0.5 Tick | 稍微加速，逐渐减少积压和延迟 |
| 比目标少了超过 0.5 Tick | 稍微减速，逐渐积累余量 |

每超出容差 1 Tick，速度调整 2%，最多加速或减速 5%。例如平滑后的余量为 5 Tick，目标为 3 Tick：误差为 2，扣掉 0.5 的容差，调整量为 1.5 × 2% = 3%，播放倍率为 1.03。

用于调速的余量经过指数平滑，避免每个网络包到达时都立刻改变速度。实现使用 `1 - exp(-2 × deltaTime)` 作为平滑系数，让平滑效果随实际经过时间变化。

目标延迟只用于调速和建立播放窗口，**不会每帧把播放头限制在“最新 Tick 减去目标延迟”的位置**。网络暂时抖动时，可以消耗预留余量继续播放；真正不可越过的边界是已收到的最新快照。

## 4. 余量耗尽：暂停并等待恢复

播放头到达最新收到的 Tick 时，将其停在该位置，设置 `_isWaitingForSnapshots`。

等待期间不推进播放头；等最新快照与播放头的差距达到 `max(1, 目标余量)` 后，再从原位置向前播放。目标余量配置为 0 时，也至少等待 1 Tick 的新内容。

恢复时把平滑余量重置为目标值，避免之前的低余量继续影响速度。这个过程不会主动把播放头往回移动。

## 5. 生成画面：取播放头前后的两条快照

`PresentEntity()` 从该实体缓存中寻找包围播放头的两条快照：

```text
前一快照 Tick <= 当前播放 Tick < 后一快照 Tick
插值比例 = (当前播放 Tick - 前一快照 Tick) / 两条快照的 Tick 间隔
```

例如播放到 103.5，前后快照分别为 103 和 104，插值比例就是 0.5。位置使用 `Vector3.Lerp`，模型旋转和视角旋转使用 `Quaternion.Slerp`，得到两条快照之间的画面姿态。

离散状态不能取中间值。播放头跨过某条快照后，`ApplyCrossed()` 按时间顺序恢复已跨过的状态，并记录已经应用的 Tick，避免重复应用。随后再写入当前播放时刻的插值姿态。

如果某个实体的播放位置早于它最旧的快照，直接显示最旧快照；如果已到达或超过它最新的快照，直接显示最新快照。当前实现不进行超出最新快照的运动外推。

## 6. 缓存淘汰与清理

长时间停顿后，如果共用播放头已经早于整体缓存的最旧 Tick，原来的素材已不可用，就重新定位到目标播放位置，恢复缓冲余量。这种情况允许向前跳转。

失活实体的缓存会被清除。所有实体记录都被清除后，重置播放状态；`Clear()` 则清空全部缓存和播放状态，供会话结束等场景使用。

## 对应代码入口

| 方法 | 职责 |
| --- | --- |
| `AddFrame()` | 接收并缓存实体快照 |
| `Present()` | 建立或恢复播放窗口，推进播放并更新各实体画面 |
| `CanStartPlayback()` | 判断初始缓冲是否足够 |
| `AdvancePlayback()` | 计算余量、调速、耗尽等待与恢复 |
| `PresentEntity()` | 查找前后快照，计算插值比例 |
| `ApplyCrossed()` | 应用播放头已跨过的快照状态 |
| `InterpolatePose()` | 输出位置和旋转的插值姿态 |
| `Clear()` | 清空缓存与播放状态 |
